In every documented deployment the api listens on loopback behind the mandatory TLS proxy (security-model §9, compose), so that address is the proxy's for every client. `check_rate_limit()` keys the second limiter on it: after `login_ip_failure_threshold` (20) failures from *anyone*, every login, `/session/reauth` and TOTP confirm answers 429 while `age < delay`, and `delay` doubles up to 900 s. ## What was checked and found correct

### Write client (`claude/ovlm-write-client`)

- **Allowlist before any mutating request.** `install_write_guard()` wraps `keystoneauth1.session.Session.request`, the single method every SDK proxy, raw `conn.<service>.post/put/delete` and the auth plugin go through (`allowlist.py:264-279`). Classification is a pure function of (method, service type from `endpoint_filter`, anchored relative path, JSON body); `data=` bodies, absolute URLs, query strings and traversal are refused; a request that matches no rule raises before anything is sent. The token request passes under the same narrow rule as the read-only guard (`guard.py:26-33`). Tested against a real keystoneauth session with a canned transport (`test_session_refuses_without_sending`, `test_sdk_proxies_cannot_delete_or_create_volumes_or_fips`, `test_backend_operations_send_exactly_the_allowlisted_requests`).
- **Never delete a volume or a floating IP, by construction.** `RULES` holds nine entries (`allowlist.py:149-174`); there is no rule for any `DELETE` on `volumes`, `snapshots`, `floatingips`, `ports`, no `POST /volumes`, no `POST`/`DELETE /floatingips`, no security-group write, and `_fip_update_ok` requires a non-empty `port_id` (no disassociation). `WriteClient` has no method for any of them (`test_volume_and_fip_deletion_do_not_exist`). The replace-all forms `PUT …/tags` and `PUT …/metadata` are absent; the claim can only `PUT …/tags/ovlm:*` and `POST …/volumes/{id}/metadata` with `ovlm.*` keys (`_volume_metadata_ok`), which is the add/merge-only condition of ruling (b).
- **Ownership guard: DB and tag, rule 1 first.** `OwnershipGuard.registration()` consults the registry on every call (`ownership.py:146-155`), and the registry protocol requires an uncached DB read; rule 2 re-reads the resource from OpenStack immediately before the call and never grants anything rule 1 refused (`test_the_marker_alone_never_grants_authority`, `test_registration_removed_mid_run_takes_effect_at_the_next_call`). Rule 3 (`check_delete`, `ownership.py:200-229`) requires `deletable`, the marker, this run's tag for created servers, no registered volume attached and `delete_on_termination` exactly `False` from both sources, with unknown counted as unsafe. The claim methods check rule 1 only, read back after the call and raise `ForeignMarkerLossError` if a pre-existing tag or key is gone or changed (`write.py:278-333`), with the 50-tag limit as `fatal`. The floating-IP move verifies that the target port's `device_id` is a registered, tagged server (`write.py:371-390`), so the FIP cannot be pointed at a foreign VM.
- **Fence hook placement.** The gate is checked in the transport, after classification and before the send, with `connect_retries=0`, `status_code_retries=0`, `redirect=False`, `allow_reauth=False` so one gate check covers exactly one send (`allowlist.py:255-276`); `FenceLost` is a `BaseException` and propagates through the client (`test_fence_lost_is_not_an_exception_steps_can_swallow`). With no gate bound on the thread the transport refuses (`GateBinding.check`), and `GuardedWriteClient` binds the step's gate around every method (`_gated`). The fake models the same boundary before touching state.
- **Credential handling in logs.** `sdk_write.py` logs only the created server id; the `adminPass` in the create response is discarded (`sdk_write.py:226`); `CreateServerSpec.user_data` is excluded from `repr`; error translation uses the body's `message` only; keystoneauth masks `X-Auth-Token`/`X-Subject-Token` in its own header logging and sends the token request with `log=False`. The remaining path is DEBUG body logging (SEC-C-2).
- **Idempotency and worker-only use.** Every method re-reads and sends nothing when the goal is reached; `create_server` requires the intended ledger row and both tags at create and refuses to create when a tagged server with the name exists; `connect_write` refuses outside `process_role == "worker"` and installs the guard before the first request; the api cannot import the package (import-linter contract and `test_import_boundaries`).

### RBAC (`claude/ovlm-rbac`)

- **Matrix.** `MATRIX` (`authz.py:88-112`) is written out per action and matches security-model §3.1 line by line, including admin not inheriting operator or approver, `human_only` on approvals, confirmations, user, credential and settings management, and token scopes (`test_matrix_cell` is table-driven over role × action; `test_matrix_rule_flags_match_the_design`). Tokens are narrowed to viewer/operator by `token_grants` and can never do a `human_only` action (`token_may`).
- **Project scoping, 404 for out of scope.** Every list query is filtered with `visible_projects()` (`None` = global, empty set = nothing), every detail lookup carries `projects=`, and changes are checked in the resource's own project with `ensure_scope()` after the lookup, which answers the same 404 for "missing" and "not visible" and 403 only for a visible resource (`authz.py:216-228`; `test_every_resource_of_another_project_is_404`, `test_operator_of_another_project_gets_404_on_changes`, `test_project_scoped_token_sees_only_its_project`). Related rows of a server or managed VM are taken from its own project only.
- **Requester sets and self-approval.** `RequesterSet` carries the five roles of the design; `evaluate_eligibility()` is one pure rule set used by the api (`check_approval_eligibility`) and the worker (`revalidate_approval_evidence`); a requester-set member or an operator+approver holder is refused unless the installation setting is on, in which case G1/G2 approvals are flagged `self_approved`; G3 refuses both cases always and requires a decider distinct from the earlier gates (`sod.py:144-208`; `test_retirement_self_approval_refused_even_with_the_setting_on`, `test_solo_installation_cannot_retire_without_a_second_human`).
- **Approval-evidence re-validation.** The seven checks are evaluated as of `decided_at` from role-binding history (`role_held_at`), the consumed step-up row (user, session, action, target, `password+totp`, issued ≤ 5 min before the decision, consumed before expiry), the user's `disabled_at`, and the installation-setting history (`installation.get_setting(at=…)`); the hash and the typed confirmation are compared with `hmac.compare_digest`; a `self_approved` flag without the setting at `decided_at` fails (`sod.py:400-550`; `test_checks_are_historical`, `test_role_or_setting_gained_after_the_decision_does_not_count`, `test_stepup_evidence` parametrised over mutations). The `installation_setting` table is append-only with a trigger and the worker holds `SELECT` only (`auth_0002` migration).
- **Admin user management.** `POST /users` has no password field (unknown fields are refused), creates the user `pending_enrolment` and returns a one-time link; resets issue a new link and clear TOTP; links are SHA-256 at rest, single-use via one atomic `UPDATE … WHERE used_at IS NULL`, revoked by a newer link; operator+approver in one scope is refused at user creation and at binding creation; an admin cannot change their own bindings while another admin exists; account provenance (created by, credential reset by) is exposed for the G3 page.

### `main` context

Argon2id with dummy-hash verification on unknown users, generic failure, per-account backoff with no hard lockout; server-side sessions stored as SHA-256 with `__Host-` cookie, `HttpOnly`, `Secure`, `SameSite=Lax`, rotation on privilege change; CSRF synchronizer token plus Origin check for cookie sessions, double-submit cookie for pre-session forms, tokens exempt; TOTP secrets encrypted with an api-side Fernet key from a secret file (SEC-R-16 part), one-time acceptance of a time step under a `FOR UPDATE` row lock, constant work across the window; single-use step-ups bound to session, action and target, consumed in the authorising transaction; API tokens hashed, expiry ≤ 90 days, scope ⊆ owner's bindings; audit rows inserted in the caller's transaction and mirrored to the log stream after commit, `INSERT, SELECT` only for both runtime roles plus triggers; CSP, `nosniff`, `Referrer-Policy`, route templates (not raw paths) in request logs so one-time link secrets are never logged.
