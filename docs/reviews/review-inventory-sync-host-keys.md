## Verdict

**Fit for the Felcloud lab: yes.** The lab's threat model is a disposable project with the OVLM operator in control
of the api host and the database; IS-1 needs a compromised api or the `ovlm_api` role, which that lab does not
exercise. Everything the lab relies on holds: the read credential is used only through the bound endpoint, the
secret reaches no record, the sync route is scoped and race-free, a token cannot confirm a host key, a re-scan
cannot replace a confirmed one, and plans are refused until confirmation. Keep lab step A2's out-of-band comparison
mandatory (IS-2).

**Must be fixed before any use beyond a disposable lab:** IS-1 (insert guard, tombstone, confirmation cleared on
fingerprint change, live re-check at the first blue SSH). Recommended with it: IS-3 (one address rule for scan and
renewal) and IS-4 (reason codes instead of exception text for viewers). IS-2, IS-6 and IS-7 are hardening and
documentation.
